Adding BM25 Hybrid Search to Your RAG Pipeline

Combining keyword search with vector search for a C# + ChromaDB + Ollama system

BM25 can be a very good addition, especially for your RAG application. But I would not replace Chroma / vector search with BM25. Instead, I'd use hybrid search:

Core idea BM25 (keyword search) + vector search (semantic search) → combine / rerank results → send best chunks to Ollama.

Why BM25 helps your project

Your current vector search can struggle with things like:

  • exact document names
  • IDs
  • error codes
  • product names
  • technical terms
  • names / numbers
  • exact phrases

For example, if the document contains:

SQL Error 18456 Login failed for user

A semantic embedding search might find related authentication content, while BM25 is very good at finding the exact 18456 and Login failed terms.

Combining results with Reciprocal Rank Fusion (RRF)

I'd recommend Reciprocal Rank Fusion (RRF) for combining BM25 and vector results rather than trying to directly compare BM25 scores with Chroma distances. Their scores are on completely different scales.

For example:

BM25 ranking

  1. Document A
  2. Document B
  3. …
  4. Document C (rank 5)

Vector ranking

  1. Document C
  2. …
  3. Document A (rank 3)
  4. Document D (rank 4)

RRF can combine those rankings without requiring the scores to have the same meaning.

My recommendation for your project

Given you're building a C# + ChromaDB + Ollama RAG system, I'd use:

Recommended approach BM25 + vector search + RRF → Ollama

rather than relying solely on vector similarity.
